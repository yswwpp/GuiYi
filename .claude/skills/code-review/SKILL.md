# Code Review Skill

对代码变更进行审查，确保代码质量和一致性。

## 触发时机

- 完成功能开发后
- 创建 Pull Request 前
- 重要模块修改后

## 审查清单

### Python 后端代码审查

1. **代码质量**
   - [ ] 类型注解完整且正确
   - [ ] 函数职责单一，长度合理（<50 行）
   - [ ] 无重复代码，可复用部分已提取
   - [ ] 异常处理完善，错误信息清晰

2. **架构规范**
   - [ ] 适配器模式正确实现（数据源隔离）
   - [ ] 同步引擎逻辑清晰（变更检测、增量更新）
   - [ ] API 路由设计合理（RESTful、错误响应）
   - [ ] 数据库操作正确（事务、连接管理）

3. **安全性**
   - [ ] 无硬编码凭证（使用 keyring）
   - [ ] 无 SQL 注入风险（使用参数化查询）
   - [ ] 无敏感信息泄露（日志、错误消息）

4. **性能**
   - [ ] 数据库查询优化（索引、批量操作）
   - [ ] 向量索引构建合理（批量索引）
   - [ ] 文件 I/O 高效（异步、缓冲）

### Swift 前端代码审查

1. **代码质量**
   - [ ] SwiftUI 视图职责清晰
   - [ ] 状态管理合理（@State、@ObservedObject）
   - [ ] 内存管理正确（避免循环引用）

2. **用户体验**
   - [ ] UI 响应流畅（异步操作不阻塞主线程）
   - [ ] 错误处理完善（用户友好提示）
   - [ ] 快捷键冲突检查

3. **API 集成**
   - [ ] 网络请求正确（URLSession、错误处理）
   - [ ] 数据模型匹配（请求/响应格式）

## 执行步骤

1. 检查变更文件列表
2. 逐文件审查代码
3. 标记问题和改进建议
4. 生成审查报告

## 输出格式

```markdown
## 代码审查报告

### 审查范围
- 文件数量：X
- 变更行数：+X -X

### 问题列表

#### 🔴 高优先级
- [ ] 文件:行号 - 问题描述

#### 🟡 中优先级
- [ ] 文件:行号 - 问题描述

#### 🟢 低优先级
- [ ] 文件:行号 - 问题描述

### 改进建议
- 建议 1
- 建议 2

### 总体评价
- 代码质量评分：X/10
- 是否可以合并：是/否
```

## 使用方法

```bash
# 审查当前变更
/review

# 审查指定文件
/review guiyi-server/adapters/web_scraper.py
```
